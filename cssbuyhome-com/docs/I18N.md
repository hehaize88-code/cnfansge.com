# CSSBuy Home localization

The supported language list lives in `src/data/config.mjs`. English uses `/`; every other language uses `/{locale}/`. Article slugs stay stable across languages so the language selector can retain the current page, query parameters and fragment.

Each language has two source files:

- `ui-{locale}.json`: navigation, page introductions, product controls, notices and labels.
- `editorial-{locale}.json`: the complete ten articles, 28 FAQs and source titles. Every section, paragraph and takeaway is retained.

Additional shared interface labels are in `ui-extra.json`. `content.mjs` merges those labels with the locale's UI file. There is no English fallback for missing translated content.

Keep IDs, article slugs, source IDs, dates, URLs and policy numbers unchanged when translating. Localize source titles and all prose. The original cnfansge product names, photos, marketplace IDs and prices remain source data; the site does not create translated product records or a separate database.

Astro creates a complete page set for each language. Canonical URLs, HTML language, reciprocal hreflang links and x-default refer to the equivalent page. The Worker reads the rendered page's language and UI dictionary when inserting catalog results, product details or source-error messages. Cards, pagination and gallery-guide links keep that language prefix.

`npm run build` checks content completeness and builds every page before packaging. `tests/localization.test.mjs` rejects missing locales, missing paragraphs, copied English body text, changed source references and altered key policy numbers. `scripts/check-localized-build.mjs` checks the generated routes, selectors, metadata, article/FAQ counts and localized runtime error states. The separate live-source integration script exercises catalog/search/product rendering in every language against cnfansge.

When editorial facts change, update all languages before publishing. Keep the existing official-source references and review date accurate. Do not add a language to navigation until its complete content has passed validation. Preview deployment stays noindex; enabling production indexing and binding cssbuyhome.com are separate deployment steps.

The Worker package deduplicates each language’s repeated footer/UI dictionary before compression. The complete page corpus stays embedded in the existing Worker; no data store or new binding is required. Static editorial routes are checked to ensure they never trigger catalog SSR.
